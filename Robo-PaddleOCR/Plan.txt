Implementation Plan - ROBO1040 Custom OCR Extraction Service
This implementation plan outlines the architecture, code changes, and verification plan for developing a custom, self-hosted OCR extraction model and FastAPI microservice for the ROBO1040 tax documents.

User Review Required
IMPORTANT

Scanned vs. Digital PDFs Our analysis of the sample PDFs revealed that many documents are scanned/vectorized images with zero directly extractable text. To handle this:

The system will use a hybrid approach: Direct PDF Text Extraction (fastest and 100% accurate for digital PDFs), falling back to OCR Page Rendering & OCR Text Detection/Recognition (using PyMuPDF for rendering and PaddleOCR/Tesseract for recognition) when digital text is missing.
We will deploy PaddleOCR/Tesseract inside the Docker container to ensure OCR is self-hosted and offline.
WARNING

Validation and Matching Schemas The spreadsheet All Forms Fields.xlsx outlines schemas for over 20 different forms, but we only have sample documents for 5 types (W-2, 1099-INT, 1099-DIV, Brokerage Statement, 5498-SA).

The initial codebase will implement fully working parsers for the 5 forms with sample data.
We will write a modular parsing framework so that the remaining 15+ form types can be added rapidly once sample documents are made available.

Core Pipeline Modules
[NEW] 
main.py
Initialize FastAPI app.
Configure CORS, TrustedHostMiddleware, and security headers (CSP, HSTS, X-Frame-Options).
Define the POST /api/v1/extract endpoint:
Reads PDF file payload.
Checks API Key validation via dependency injection (X-API-Key header).
Runs the classification and extraction pipeline.
Returns JSON containing document_type, extracted_data, and processing metadata.
Define GET /health endpoint for health checks.
[NEW] 
auth.py
Implement API Key authorization middleware.
Extract verification key from environment variables (fallback to a default test key if none set).
Append security response headers to all responses.
[NEW] 
classifier.py
Scan the first few pages of the document.
Use anchor strings to classify the document type:
"Form W-2" / "Wage and Tax Statement" -> W2
"Form 1099-INT" / "Interest Income" -> 1099-INT
"Form 1099-DIV" / "Dividends and Distributions" -> 1099-DIV
"Form 5498-SA" / "HSA, Archer MSA" -> 5498-SA
"Consolidated Brokerage Statement" / "Goldman Sachs" -> Consolidated Brokerage Statement
[NEW] 
ocr_engine.py
Implement text extraction pipeline:
Try direct extraction using PyMuPDF text APIs.
If the extracted text has a character count below 100, render pages as images and apply PaddleOCR to transcribe text with coordinates.
Return structured text lines with spatial information (bounding boxes) for accurate spatial regex anchoring.
[NEW] 
parser.py
Implement format-specific parsers mapping raw OCR text blocks to target keys:
W-2: Extract SSN, EIN, Wages, Federal tax withheld, Employer name/address, Zipcode.
1099-INT: Extract Payer TIN, Recipient TIN, Interest Income, Federal tax withheld.
1099-DIV: Extract Payer TIN, Recipient TIN, Ordinary dividends, Qualified dividends, Capital gain.
5498-SA: Extract Trustee TIN, Participant TIN, HSA contributions.
Consolidated Brokerage Statement: Extract Payer/Recipient names, Taxpayer details, and transaction table items.
